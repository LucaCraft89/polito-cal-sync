# 041 Server deployment: the page on, published on all interfaces, reachable by IP

**Context.** The owner deployed it on a server and asked for the shipped `.env` to enable the web page and bind `0.0.0.0` by default, and to leave out every setting that the page can change (a variable that is set wins over the page and locks the field, which is annoying).

**Decided**

- **`.env.example`**: only infrastructure is active: `UI_ENABLED=true`, `BIND_ADDRESS=0.0.0.0`, `STATUS_BIND=0.0.0.0`, `STATUS_PORT`, `LOG_LEVEL`. **Every setting that also exists in the page is commented out** (time zone, interval, limit, Google client, calendars, feeds, Polito, Moodle, squads, exclusions), with a note why. `docker-compose.yml` publishes `${BIND_ADDRESS:-127.0.0.1}:8787` and sets `UI_ENABLED` to true by default; **without a `.env` the default stays this-machine-only**, the open default is the owner's choice made by copying the example. `TZ` is still set by the container (the compose file and the image), so the page shows the time zone as locked; change it with `TZ=` in `.env`.
- **The page answers an IP address in the Host header** (`192.168.1.20`, `[fd00::5]`), not only `localhost` and the names in `UI_ALLOWED_HOSTS`. Why this is safe: DNS rebinding needs a NAME the attacker controls; a request whose Host is an IP is one the person typed or a plain cross-site request, which the Origin, `Sec-Fetch-Site`, CSRF-token and `SameSite=Strict` checks already stop. Names that merely contain an address (`192.168.1.20.nip.io`) are still refused. Without this, binding to `0.0.0.0` would only give "this address is not allowed" from every other device.
- **Unchanged on purpose:** the **first-run step (choosing the passphrase) works only with a `localhost` Host**, so nobody who can reach the port can take the page over before the owner; the sign-in port 8789 stays published on `127.0.0.1` only (Google sends the browser to `127.0.0.1`, so Google must be connected from the server itself or through an SSH tunnel of 8787 and 8789). The honest limit, in the README and `.env.example`: **no HTTPS**; use a trusted network, a VPN or a TLS proxy (`UI_HTTPS`).

**Verified how.** A test: IP hosts (v4 and v6) are answered for the API and the page and a login works through them with the matching Origin; look-alike names are refused (421); the first-run setup through an IP Host is refused (421). `docker compose config` validates.
