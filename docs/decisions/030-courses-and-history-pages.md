# 030 Courses and History pages, the course list file, the paused login

**Decided**

- **Course list file.** Every read of the portal (dry run or real run) saves the course names and the squad labels seen to `DATA_DIR/courses.json` (0600, atomic; `src/sources/polito/catalog.ts`). Names and squad labels only: no lessons, rooms or titles. A read that returned no courses never overwrites it. It lets the Courses page and the squad picker work after a restart without another university login (the preview is only kept in memory and limited to one per 15 minutes). A dry run writing this cache is like it already writing the ICS cache; it still writes no event and no history row. `GET /api/courses` merges it with the chosen squads from the settings. The Sources page now takes its squad checkboxes from `/api/courses` instead of the last preview.
- **Courses page:** each course with its squads seen and yours marked (icon + word), a note when none is chosen (all kept), and a link to Sources to change them. Choosing stays on Sources. **Not built:** naming Moodle courses (`course-names.json`) and per-course calendars (decision 013): no Courses-page feature needs them yet, and they are the large part of 013 (two-phase run, moves, per-calendar limits).
- **History page** `GET /api/history`: the last 30 runs (up to 100) from sqlite, opened **read-only** (`StateStore.recent`; unlike `open` it does not mark a running row as interrupted), counts, status, "limit confirmed by hand", failures by code, incomplete sources, and the error in the three-line form. A run row stores only the **code**, so the text is the generic one read from `docs/ERRORS.md` (`src/util/error-docs.ts`; the Dockerfile now copies that file; without it the page shows the code and the docs reference). Also the scheduled loop's last state from the heartbeat file, and the paused login.
- **Paused login and "I fixed the credentials".** The page shows a pause only if the latch matches the **current** credentials. `POST /api/sources/polito/resume` clears the latch for them, audit `polito.login.resumed`, and makes **no request by itself**: the next sync/test/preview logs in once. If the university refuses again the latch is written again. A confirm dialog says so. No extra rate limit on the button (the login test and preview limits and the latch bound the traffic; a person pressing it repeatedly can cause one refused login per press, which the dialog warns about). The text of `E_POLITO_LOGIN_BLOCKED` now names the Sources page and this button.
- **Navigation:** five destinations (Overview, Preview, Sources, Courses, History) in the bottom bar / rail / drawer as UI.md section 5 says; **Settings is the gear in the top bar** (48 px, `aria-current` when open). Browser tests adjusted for it.

**Verified how.** `test/web-history.test.ts` (6 cases: auth, empty, list order and that an open run is not touched, three-line text from the docs, paused login only for current credentials, resume + CSRF + audit, a refused preview latches) and a Playwright test at 360 px on populated Courses and History pages (layout, axe light and dark, the dialog, no request on resume); all older layout/axe tests pass with the new nav. Nothing real was contacted.
