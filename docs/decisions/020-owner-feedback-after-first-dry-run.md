# 020 Changes after the owner's review of the first live dry run (2026-11-04)

**Decided**

- **Exam calls: booked only, by default** (`POLITO_EXAM_CALLS=booked`; `all` brings every open call back). A call counts as booked if its `status` is `booked` **or** it has a positive `idBooking` (both held for the one booked call in the sample). Every call is still validated, so an unreadable unbooked call keeps the run incomplete (nothing is deleted on a guess). Consequence: switching from `all` to `booked` later deletes the unbooked calls we wrote, which is the intent.
- **Moodle events are labelled.** Events from an ICS feed whose host equals the host of `MOODLE_BASE_URL` (default `https://moodle.polito.it`) get kind `moodle` and the title prefix `[Moodle] `; the prefix is what shows in Google Calendar (kind is stored in a hidden property). The identity (`sourceId`) is unchanged, so turning this on is an update, not delete + create. Decision 009's "kind is always `lecture`" now holds only for feeds that are not on the Moodle host. A Moodle deadline ("... apre/chiude") is still not told apart from other Moodle events.
- **Squads (parallel groups) are not filtered yet.** The owner explained that same-slot duplicates are other squads of which the student is in only one. The portal returns them anyway, and the sample shows no field that identifies the student's squad (lessons carry `id`, `courseId`, `type`, `description`, `teacherId`, `place`). Guessing from `description` or `place` would drop real lectures, which is the wrong kind of error. `sync --dry-run --details` now prints course, place and note under each planned event, so the field that tells squads apart can be found in the owner's own data; then a filter is a small change.
- **The owner will not write to their Google calendar yet.** The dry runs are the proof for M3; the second-run no-op is covered only by the tests against the fake Google calendar (M2 flow) and by the unchanged ids, not by a real run.
