# 035 Moodle probe 08 result: the web service holds nothing the custom export lacks (today)

**Observed** (owner run, 2026-11-05, 22 requests, counts only).

- The month view for 8 months holds **31 distinct events**: exactly the 31 of `core_calendar_get_calendar_events`. The earlier "52 events this month" were **multi-day events repeated on every day** (52 occurrences, 18 distinct ids in November). Nothing is hidden from the event query: `monthlyOnly = 0`.
- Export, custom range: 18 events (1 Nov 2026 to 1 Oct 2027). Event query: 31. In both: 17. In the query but not the export: 14, **all in October (the past)**, 10 `reservation` and 4 `quiz` events. There are no Moodle events after November in these 5 courses at all.
- Every event is a course-module event (`isactionevent` true, `normalisedeventtype` course): 26 `mod_reservation`, 5 `mod_quiz`. No assignments, no lessons, no user or site events, no group events. Course ids are in every event.

**What this means.** On this account and today, the export link with **Custom range** is as complete as the web service for everything from the start of the current month on. The web service adds: the past (the export starts at the first of the month), the course of each event, the activity link (`viewurl`), no link to copy or regenerate, and the same window we choose ourselves. The "missing events" reported earlier are explained by the export's time window: "Recent and next 60 days" and "This month" stop after about 15 days; only Custom range reaches a year. Whether the owner also saw events the data above does not contain is not known; nothing in the three comparisons is missing from the query.

**Decided.** Do not build the Moodle web-service source yet. Cost: the program would store the university password for Moodle too (it already may for the portal), run a second SSO login per sync (about 9 requests), and depend on a token whose lifetime is unknown. Benefit today: past events and course names. Recommended first: switch the feed to the Custom-range export link and see whether anything is still missing. If something still is, or the owner wants past events and course names, the source is straightforward (the shapes are now known: `core_calendar_get_calendar_events` for the window, `core_enrol_get_users_courses` for course names, `core_calendar_get_calendar_export_token` to rebuild the link) and is built next; the probes `06` to `08` stay as the evidence.
