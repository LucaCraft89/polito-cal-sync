# 024 Web UI: design system, app shell, serving (M5 step 2)

**Decided**

- **Files.** The UI is static: `web/` at the repository root (`index.html`, `assets/*.css`, `assets/*.js` as ES modules, one self-hosted font). It is served by `src/web/static.ts` from the same `node:http` server as the API (decision 023). All files are read once at start into a map keyed by exact path, so there is nothing to traverse; unknown types are never served; a foreign `Host` gets 421; `GET`/`HEAD` only. Same security headers as the API except `Cache-Control: no-cache` + `ETag` (revalidate, 304), so an upgrade shows at once. `web/` resolves the same from `src/web` and `dist/web`; the Dockerfile copies it. `/` is the UI when `UI_ENABLED=true`; `/status` and `/healthz` are unchanged.
- **Pages are plain static HTML + small scripts**, not server-rendered templates (UI.md allowed both). Untrusted text only ever enters the DOM through `textContent`/text nodes (`web/assets/dom.js`); a test fails if any client file uses `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, an inline `style` attribute, or contains a third-party URL. No framework, no build step beyond what exists; `noscript` explains that scripts are needed.
- **Tokens.** `scripts/palette.ts` derives colour roles from one seed (blue, hue 262) as tonal palettes (CIE L* tone, LCh hue/chroma, clamped into sRGB) and fills the Material 3 role names (`--c-primary`, `--c-on-primary-container`, `--c-surface-container-high`, ... plus our own `success` and `warning` roles). **This is our own approximation of Material 3's tonal palettes, not the Material Color Utilities (HCT) algorithm**: close to Material's colours, not identical. `pnpm tokens` writes `web/assets/tokens.css` (committed, excluded from prettier); a test fails if it drifts. Light and dark follow `prefers-color-scheme`; `data-theme` overrides it (Settings > Theme, kept in `localStorage`, applied by `theme-init.js` before first paint). Shape scale with expressive leaf shapes, 4 px spacing grid, type scale with emphasised variants (heavier, wider), motion tokens with spring curves as CSS `linear()` (a damped oscillator sampled in `palette.ts`; overshoot for spatial motion, none for effects).
- **Font.** Roboto Flex (SIL OFL 1.1), latin subset, variable weight, 34 KB, taken from the npm package `@fontsource-variable/roboto-flex` 5.3.0 and committed with its licence (`web/assets/fonts/OFL.txt`). No CDN. Fallback `system-ui`. Latin only: Italian accents are covered; other scripts fall back to the system font.
- **Components** (`components.css`, vanilla): top app bar, navigation (bottom bar below 600 px, 96 px rail from 600, 280 px drawer from 840), filled/tonal/outlined/text/danger buttons, button group, extended FAB (one per page), outlined text fields with help and error, switch, segmented control, status and filter chips (icon + word, never colour alone), cards, list items, banners (info/ok/warn/bad), modal `<dialog>`, snackbar (live region), linear progress and a morphing loader with a word next to it, three-line error form. Icons are drawn by us as inline SVG.
- **Accessibility and motion.** Skip link, landmarks, one `h1` per view, labelled controls, focus ring everywhere, `scroll-padding` so a focused control is not hidden behind the sticky bars (found by a test, see below), `prefers-reduced-motion` sets all transitions and animations to ~0.
- **Tests** (`test/web-static.test.ts`, `test/web-ui.browser.test.ts`). Browser tests drive real Chromium through Playwright 1.63.0 (devDependency): 360x800, 390x844, 768x1024, 1280x800 on login and each page: no horizontal scroll (also 320 px), every control at least 48 px, navigation is the right shape for the size class (also when the window is resized), main action visible and not under the bar, axe-core 4.10.2 (devDependency, offline) on every page in light and dark with **no serious or critical finding**, keyboard-only walk with a visible focus on every control, focused controls never behind the bars, reduced motion, theme, CSP/page-error/foreign-request watch on every page. A palette test checks WCAG AA contrast for every text/background pair the UI draws, light and dark. **Finding by the tests:** with the sticky bars, Tab could focus a button hidden under the bottom bar; fixed with `scroll-padding`. The test was checked to fail without the fix.
- **axe's `target-size` rule is switched off** (it counts a sticky bar overlapping a control at the current scroll position, a false alarm once scroll-padding is in); our own 48 px check and the "never hidden" test replace it.
- **CI.** The browser tests are skipped when no Chromium can start, except with `REQUIRE_BROWSER=1`, which CI sets after `playwright install --with-deps chromium`. A missing browser in CI is a failure, not a silent skip. `test/web-ui.browser.test.ts` references the DOM lib for the code it evaluates in the page, which makes DOM types visible to the whole TypeScript project (not to the runtime).
- **Not done / honest limits.** Not the official Material implementation. Visual check by screenshots at 390 and 1280 px only (no designer). Error banners show `docs/ERRORS.md#e_x` as text: the UI does not serve the docs, so the link is not clickable (open decision: serve ERRORS.md, or link to the repository once it is public). Fonts: Latin only.
