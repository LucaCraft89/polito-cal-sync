# 032 `doctor`, the setup checklist (first-run wizard) and the docs

**Decided**

- **`doctor`** (`src/doctor/index.ts`, `pnpm run doctor`, `--local` = no network): data folder writable and private (warns if group/other can open it), clock (year plausible) and time zone, history database, Google (client saved, login saved, calendar chosen, then `assertDedicatedCalendar`: reachable, not the main calendar, writable), each feed (one unconditional GET, one attempt, no cache), the Polito portal (the portal source's own login and read; a paused login is reported with **no request**, a refused one latches as everywhere), last sync (from the read-only run table; failed or refused is a warning with its code; the scheduled loop's health from the heartbeat). Statuses ok / warn / fail / skipped; exit 1 only on fail. Output: counts and names we may show, problems in the three-line form with the docs anchor; no addresses, event text or secrets. It only reads. Sleeps 1 s between feeds. Clock check is local only (a skew against a server was not built).
- **First-run wizard = an ordered checklist on Overview** instead of a separate modal flow: 1 Google client, 2 connect, 3 calendar, 4 a source on, (5 Polito login), then first preview and first sync; the first undone step is shown as "Next" with a button that goes to the right page (Settings, Sources, Preview). The passphrase step is the existing first-run page. Each step has its own Test/Preview button where it lives, so there is no second copy of the forms. Resumable by construction (it reads the saved state).
- **Docs:** `docs/SETUP.md` (start, Google Cloud console steps incl. the Testing vs In-production trap, connect, sources, preview and sync, doctor, Moodle notes, limits), README status rewritten and honest about what was run (**nothing against real Google**). `docs/ERRORS.md` has every code (a test enforces it); no new codes in this step.
- **Not done:** screenshots for the README (need a person to look at them), per-course calendars, the Moodle web-service source (waiting for probe 06).

**Verified how.** `test/doctor.test.ts` (10 cases with fake calendars, an in-memory feed and the invented portal: all fine, not connected, missing client, main calendar, read-only calendar, a refused feed without the token in the output and one GET each, no source, paused and refused login with no repeat, `--local` contacting nobody, wrong clock, last run refused, CLI exit codes); the browser tests cover the new Overview. Nothing real was contacted.
