# 014 How the owner-run probe protects the owner

**Decided**

- **Plain `.mjs` under `probe/`**, Node >= 22, no new dependency; `probe/lib` is imported by unit tests (`test/probe-lib.test.ts`), and the scripts were exercised end to end (hidden prompt included, through a pseudo-terminal) against an invented local server. They were **not** run against Polito from the build session: recon that needs the owner's credentials runs only on the owner's machine, and even the unauthenticated step 1 is left to the owner.
- **Credentials:** hidden prompt only (raw-mode stdin, no echo); refuses to run without a terminal; never argv, env or disk; held in local variables of one process. Step 3 logs in again instead of reusing a token from step 2, so no token ever touches the disk.
- **Raw answers are never saved.** Step 2 stores status codes, a few allow-listed headers (no cookies, only cookie _names_), response shapes (key names, types, string lengths) and short server error texts scrubbed of anything the owner typed. Step 3 redacts in memory and writes only the sanitized copy.
- **Shape check with a fake login first** (one request, user `probe-no-such-user`): the real password is only sent once the server has shown it understands the request shape (401/403 = shape accepted; 400/415/422 = shape wrong, stop). The body (`type: basic`, `username`, `password`, `preferences: {}`) is a guess from the spec summary; `--body-template` lets the owner fix it without code changes. Cost: one extra request with fake credentials; `--no-shape-check` skips it.
- **Sanitizer is default-deny** (see `probe/lib/sanitize.mjs`): strings survive only as dates or enum-looking words under enum-like keys; names, titles, rooms, links, emails and unknown strings become consistent placeholders across files; numeric ids renumbered; coordinates zeroed; `--shift-days N` moves every date by the same N. After redacting, a leak scan (email, JWT, long random strings, student numbers, URLs, anything typed) sends the files to `probe/out/needs-review/` instead of `sanitized/` if it finds something. It is a net, not a guarantee: the owner checklist stays mandatory.
- **Stop rules:** 429 always stops; 401/403 stop the data calls (step 2 still asks MFA status once when the data call is refused, because that is the evidence wanted); a login is never retried; GETs retry 5xx at most twice with backoff.
- **`--enrol`:** off unless passed, full warning, asked twice, one best-effort attempt, no retries. Key: ECDSA P-256, public key as base64 SPKI DER, signature over the nonce with SHA-256 (all **UNVERIFIED guesses** from "enrol with a public key, sign challenges"). The private key is written only after the server returned a serial, to `probe/out/mfa-device.json` (0600, git-ignored; the secret scan forbids such files in git).
- **Token header:** `Authorization: Bearer` is assumed (UNVERIFIED) and recorded as an assumption in the output.
