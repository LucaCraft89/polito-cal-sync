# 029 Sync now: the guards, in order

Sync now is the one UI action that WRITES to the dedicated Google calendar. It is built and tested **only against the in-memory calendar** (`MemoryEventsApi`) and an in-memory feed. It has never run against the owner's real calendar, and nothing in the program starts it by itself: it runs only after a person confirms a preview in the page. **The owner has not asked for a real run; none was made.**

**Decided** (`src/web/sync.ts`, `POST /api/sync`, `GET /api/sync`)

1. **Needs a fresh preview that was looked at** (`E_UI_SYNC_NEEDS_PREVIEW`, 409): the request carries `previewAt` (the `generatedAt` of the preview on screen) and `confirm: true`, nothing else. The server accepts it only if that is still the latest preview, it is younger than **30 minutes**, and the settings it was made from are unchanged (a hash of every saved setting except the interval, plus the chosen calendar, taken before the preview ran). A finished sync clears the preview, so a second sync needs a new one. Consequence: after changing a setting you wait for the preview limit (15 minutes) before you can sync from the page; the scheduled sync is unaffected.
2. **One tap to confirm** in a dialog that says how many events are added, changed and removed.
3. **Typed confirmation beyond the limit** (`E_UI_SYNC_CONFIRMATION`, 422): when the preview's safety line is exceeded, the request must carry `typed` = `remove N` (N = removals; trimmed, case-insensitive). Only then the run is `force`d (decision 001). Within the limit `force` is false, so the engine's own limit still applies.
4. **The run is held to the preview** (`guard` in `runSync`, `E_SYNC_PLAN_CHANGED`): the plan is computed again at run time; if it would remove **more events than the confirmed preview showed**, nothing is written, the run is recorded as `refused`. This also bounds a forced run to the typed number. Additions and changes are not capped (they are not destructive and sources move).
5. **Rate limit: one start per 15 minutes**, from the start of the last attempt (failed ones count). Refusals (`E_UI_SYNC_RATE_LIMITED`, 429) cost no traffic and are not counted. This is separate from the `serve` loop, which has its own schedule.
6. **Run lock** (decision 012): the real run takes `sync.lock` through `runConfiguredSync`; while `serve` or a manual `sync` holds it the result is `E_SYNC_ALREADY_RUNNING` and nothing is written. In-process single flight answers the same code (409).
7. **Background job:** `POST` answers 202 at once; the page polls `GET /api/sync` (`idle | running | done` with counts and the three-line problem). A page reload or a closed tab does not stop it. `serve` waits for it on shutdown (`web.settle()`, within the shutdown grace time). If the process is killed anyway, the stale-lock and "running row marked failed" rules of decisions 005 and 012 apply.
8. **Audit:** `sync.started` (forced, planned counts) and `sync.finished` (status, counts, error code); never event text. The run itself is a normal run row in sqlite (History page, next step).
9. **Google guards unchanged:** the real client goes through `connectGoogle` and `assertDedicatedCalendar` (never the main calendar, must be writable) and `OwnedCalendar` (only events with our marker).

**Verified how.** `test/web-sync.test.ts` (13 cases against the real HTTP server and the in-memory Google): session and CSRF, no preview, strict body, wrong/stale/changed-settings preview, the write itself with markers and a run row and an audit trail and no event text or password in any answer or log, 15 minute limit with an injected clock, single flight and `settle()`, the run lock, a Google failure, removals within the limit, the typed phrase (wrong phrases refused without consuming the rate limit), the plan-changed veto (also for a forced run). Two mutations (veto removed, freshness check removed) were confirmed to fail the tests. A Playwright test on a 390 px phone: cancel writes nothing, one-tap confirm, typed phrase gate (button disabled until exact), results, layout and axe in light and dark, hostile titles as text. **Not run:** anything against real Google or against the real portal.
