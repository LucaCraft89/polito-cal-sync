# 040 Leave Moodle courses out; keep Moodle events in a calendar of their own

**Context.** The owner is enrolled by default in a Moodle course (a mathematical lab) they never attend, and its events fill the calendar. They also want Moodle and the Polito agenda in two Google calendars, with the `[Moodle]` tag kept.

**Courses left out** (setting `moodle.excludedCourses`, env `MOODLE_EXCLUDED_COURSES`, a comma list of Moodle course ids)

- The live Moodle source drops events of those courses and does not even ask for them (their ids are left out of the query); it still reads their **names**, so a course can be switched back on. Events of a course that is switched off are removed from the calendar at the next sync through the normal deletion path, within the deletion limit (the UI says so). The Sources page lists the Moodle courses as checkboxes ("Courses to include"; unticked = left out), like the squad picker; the list appears after the first Moodle read (Test Moodle, a preview or a sync) and updates by itself. The list is kept in `courses.json` next to the Polito one (names only; merged, an empty read never overwrites it). Excluded ids the last read did not show are kept as they are.
- Only the live Moodle source honours it. A Moodle ICS feed has no reliable course id (decision 013), so it cannot be filtered this way.

**Two calendars** (setting `calendars.splitMoodle`, env `CALENDAR_SPLIT_MOODLE`; the second calendar in `google-calendar-moodle.json` or `GOOGLE_MOODLE_CALENDAR_ID`; off by default)

- **Routing.** Events of kind `moodle` (the live source, and a Moodle ICS feed) go to the Moodle calendar, everything else to the Polito calendar. Titles keep `[Moodle]`. This is the simple, two-calendar case of decision 013 (no per-course calendars).
- **Choosing the calendar.** Same picker as the first one (`slot: "moodle"`): create ("Moodle (polito-cal-sync)", reused by name if it exists) or pick; never the main calendar; the two must differ (`E_GOOGLE_CALENDARS_SAME`); an environment variable locks it; a sign-in with another Google account forgets both choices. With the setting on and no Moodle calendar, a sync stops with a plain `E_NOT_CONFIGURED` ("create or pick the Moodle calendar"); `doctor` and the Overview checklist say the same.
- **Engine** (`src/sync/split.ts`). Each calendar gets its own plan and deletion limit; the set of sources and their `complete` flag are shared, so an incomplete source deletes nothing in either calendar. **If either calendar exceeds its limit the whole run is refused and nothing is written anywhere** (unless forced). **Moves:** an event whose calendar changes (the setting switched on or off, or its kind changes) is created in the new calendar first and its old copy is deleted afterwards, only if the new copy was written (a failure keeps the old copy, the next run finishes it); moves are left out of the plan's deletions, so switching the setting never looks like a mass deletion. Preview and the Service page say how many events will move. Switched off again, the events move back and, once the Moodle calendar holds nothing of ours, the program stops looking at it. The two runs write **one** history row with the merged counts; the mirror table records each event under its calendar.
- **Safety unchanged:** only events carrying our marker are ever touched, in the two calendars the owner chose; no calendar is ever deleted; the main calendar is refused.
- **Not done:** per-course calendars, more than two calendars, colour per calendar (Google lets each calendar have its own colour in its own settings). Not run against real Google (the tests use the in-memory calendar).

**Verified how.** `test/split-sync.test.ts` (8: routing and the `[Moodle]` title, no-op second run, dry run, a mass move is not a mass deletion and the order is create-then-delete, a failed copy keeps the old one and the next run finishes it, either calendar refusing refuses all and nothing is written, an incomplete source deletes nothing, switching off moves back and reports the calendar empty, one history row), moodle source and sync tests (excluded courses are dropped, not asked for, still named; a real sync into two calendars, switched on and off, a missing second calendar), API tests (slots, same calendar refused, lock by environment, course list and exclusion with validation) and a Playwright test on a phone (course checkboxes appear after Test Moodle and are saved; the split switch, the Moodle calendar picker, the Overview step; layout and axe in light and dark).
