# 015 The Polito API source: shape, evidence and fail-closed rules

**Decided**

- **Disabled by default** (`SOURCE_POLITO_API_ENABLED=false`; any value other than `true`/`false` is `E_CONFIG_INVALID`). The ICS source is complete without it. With the switch on, the only auth that exists is `UnavailableAuth`, which fails with `E_POLITO_API_NOT_READY`: the source then makes **no network request**, the run is marked incomplete (exit code 2), the ICS events sync normally, and the error is printed. No credentials are read from anywhere.
- **Evidence table = `src/sources/polito/fields.ts`.** Every endpoint path and field name is tagged `SPEC` (named in the spec summary in AGENTS.md; still unverified against live traffic) or `GUESS` (by analogy). No lecture field is known, so all of them are `GUESS`. Mapper and schemas read names only from that file, so the probe's answer is a one-file edit. The test fixtures (`test/fixtures/polito/`) are **invented** from the table and say so; they prove the mapper, not the table.
- **Fail closed.** `complete: true` only if every endpoint answered, every list had a known shape (bare array or `{data: [...]}`, a guess) and every item passed its schema. Required: identity, title, times (date-times must carry `Z` or an offset). Decorations (location, course) never fail an item. A missing or renamed required field means: item skipped, `E_POLITO_API_UNEXPECTED_DATA` (positions and field names only, never content), run incomplete, **no deletions for this source**; items that were understood are still written. A non-list answer is a failure of the endpoint, never an empty list; a real empty list is fine.
- **Stop rules in a run:** after login refusal (401/403), 429, an outage or an internal error nothing more is requested (`not-run` in the report); a schema mismatch does not stop the other endpoints. The source never throws; `runConfiguredSync` also catches a throwing non-ICS source and treats it as incomplete, so a Polito failure can never block, delete or hide ICS events.
- **Client:** one request at a time, 1 s pause, honest User-Agent, 30 s timeout, redirects not followed (a login page is not data), 5xx/429/network retried with backoff (4 attempts, `Retry-After` honoured), 401/403 never retried and the token dropped, after an exhausted 429 no more requests in that run. Errors contain neither the token nor any body.
- **Kinds:** `/lectures` -> `lecture`; `/exams` -> `exam_call` (every entry is a call; the spec has no separate model), becoming `exam` only for statuses listed in `EXAM_BOOKED_STATUSES`, **empty until the probe shows the enum values**; the booking window end of an exam adds a `deadline` event ("Booking closes: ..."); `/bookings` -> `booking`; `/deadlines` -> all-day `deadline`; assignments -> `assignment` at `uploadedAt` (the API publishes no due date, said in the description); `/v2/courses` is read for the course ids and names, no event.
- **Identity:** `sourceId` = `lecture:<id>`, `exam:<id>`, `exam:<id>:booking-closes`, `booking:<id>`, `deadline:<id>`, `assignment:<course>:<id>`. For deadlines and assignments the API id is optional (unknown); without it a hash of title and date is used, so a retitled item becomes delete + create.
- **Window:** lectures and deadlines are requested from 90 days back to 180 days ahead (plain dates); the other endpoints have no window parameters. An event that slides out of the window leaves the calendar by the normal deletion path. Per-course assignment calls are capped at 40.
- **Traffic per run:** 5 requests plus one per course.
- **Course key:** `polito:<course id>` (opaque), see decision 013.
